# 必读！！！B 榜提交说明

## SHA 必交，缺失或不一致将取消对应成绩

**每次 B 榜提交都必须附带 `solution_commit.txt`，填写真实对应本次原始 `solution.zip` 的 SHA-256 和精确字节数。缺少声明、缺少 SHA、SHA 格式无效或声明字段错误，该次提交无效、不予计分；若已形成成绩，将取消该次提交对应的成绩。**

**赛后审核时，原始 `solution.zip` 的实际 SHA-256 必须与最终有效提交中的声明完全一致；若不一致，将取消最终 B 榜成绩。模型包字节数不一致、无法运行或无法按题面要求复现，也将导致审核不通过。**

请保存最终提交对应的原始 `solution.zip`，不要解压后重新压缩，不要在生成声明后修改原包。正式提交必须填写自己模型包的真实 SHA，不能照抄样例 SHA。格式无效的提交不计入“最后一次有效提交”；最终结果仍按截止前最后一次有效提交确定。

正式提交时只上传 `b_submission.zip`，其根目录必须且只能包含以下两个普通文件：

```text
b_submission.zip
├── result.json
└── solution_commit.txt
```

不得嵌套目录，不得添加目录条目、重复文件、符号链接或加密文件。**不要放入本说明、README、图像信息、校验工具、评分脚本、`solution.zip` 或任何其他文件。** 外层“提交样例”压缩包供下载学习，不能直接作为正式提交。

## 重点必读：SHA 登记与模型包保存

### 每次提交都要附带本次模型包声明

本题所说的 SHA 登记，是把本次完整模型包的 SHA-256 和字节数写入 `solution_commit.txt`，与本次 `result.json` 一起打包上传。只上传预测、只在其他说明中写 SHA，或只在历史提交中交过 SHA，都不能代替本次声明。

**B 榜数据发布前无需提前登记，也无需提前上传模型包；B 榜期间每一次提交都必须附带声明。** 不同次提交允许使用不同的 `solution.zip`，但结果和声明必须一一对应。比赛阶段不上传完整模型包，进入赛后复核范围后才上传最终有效提交对应的原始模型包。

SHA-256 是根据文件全部字节计算出的 64 位十六进制指纹。文件名相同不代表文件内容相同，赛后核对的是指纹和字节数。**不要手写随机 SHA、照抄样例 SHA，或把另一版模型的 SHA 填进本次声明。**

### 必须对哪个文件计算 SHA

计算对象固定为完整、可独立运行的**原始 `solution.zip` 文件**。真实参赛模型包应包含推理代码、模型权重、配置、预处理及后处理、依赖版本说明和规定的推理入口。

| 项目 | 正确填写 | 常见错误 |
| --- | --- | --- |
| SHA-256 | 完整 `solution.zip` 原始二进制字节的 SHA-256 | 对单个权重、解压目录、`result.json` 或 `b_submission.zip` 求哈希 |
| 字节数 | 同一个 `solution.zip` 的实际字节数 | 填 MB、四舍五入后的大小或解压目录大小 |
| 数据版本 | 固定为 `B-v1` | 沿用 A 榜或其他测试集版本 |

可以在该 ZIP 的解压副本中运行推理，但必须保留生成声明时的 ZIP 原文件。重新压缩时，即使代码和权重没有变化，文件顺序、时间戳和压缩参数变化也可能导致 SHA 改变。**仅保留解压目录，赛后重新打包，不能保证通过核验。**

### 每次提交按这个顺序操作

1. **准备本次模型包。** 将完整推理程序、权重、配置和依赖说明打包为 `solution.zip`，保留原始 ZIP。
2. **生成对应预测。** 使用该原包解压出的解决方案，对本次 B 榜全部图像生成 `result.json`。如果修改了代码、权重或配置，应重新打包并确认新包能复现结果，不能继续声明旧包的 SHA。
3. **生成真实声明。** 对确定好的原始 `solution.zip` 运行下方生成工具，自动计算 SHA-256、字节数和数据版本。
4. **新建提交包。** 将本次 `result.json` 和刚生成的 `solution_commit.txt` 放在 `b_submission.zip` 根目录，不放其他文件。
5. **校验并上传。** 运行公开校验器，修正错误后上传，并确认平台记录是否有效。
6. **保存整套材料。** 按提交编号或时间分别保存原始模型包、结果、声明和上传包，避免后一次运行覆盖前一次文件。截止后确认最后一次有效提交对应哪一套材料。

在附带工具所在目录，放好自己的 `solution.zip`，运行：

```bash
python generate_solution_commit.py solution.zip
```

命令在当前目录生成 `solution_commit.txt`。请保留样例中工具所需的同目录文件，不要只复制单个脚本。命令运行后如果更改了模型包，必须重新生成声明。

在本次 `result.json` 和 `solution_commit.txt` 所在目录新建提交包：

```bash
python -m zipfile -c b_submission.zip result.json solution_commit.txt
```

安装公开校验工具的依赖并检查最终上传包：

```bash
pip install -r requirements.txt
python validate_b_submission.py b_submission.zip images_test_b.json
```

若提交包不在工具目录，只需把命令中的 `b_submission.zip` 换成其相对路径。`images_test_b.json` 是公开图像清单，只含图像 ID 和尺寸信息，不含答案。

**声明生成工具负责计算 SHA 和字节数，公开校验器负责检查提交格式；两者都不能代替赛后的模型内容检查和离线复现。**

### 声明文件的五个字段

`solution_commit.txt` 使用 UTF-8 编码，采用 `key=value` 格式，必须且只能包含以下五个字段，每个字段恰好出现一次：

```text
solution_name=solution.zip
hash_algorithm=SHA-256
solution_sha256=<64位十六进制SHA-256>
solution_size=<solution.zip的正整数字节数>
b_data_version=B-v1
```

不要添加注释、空行、字段两侧多余空格或额外字段。`solution_size` 必须是无前导零的正整数，不能带单位、小数点或千位分隔符。上面的尖括号内容只是格式占位符，不能原样提交；请使用工具生成真实值。

### 多次提交与最终结果

B 榜每支队伍**总共可提交 3 次，不因日期变化重置**，期间不展示实时分数或排名。

每次提交独立对应一套“原始模型包—预测结果—SHA 声明”。换了模型包，就应使用新包的实际 SHA 和字节数；同一个原始包字节完全不变时，SHA 可以相同，但每次提交仍必须附带声明，且该包必须能复现相应预测。

平台按服务器接收时间和提交编号确定截止前的**最后一次有效提交**，不取历史最高分。最后上传的一包若格式无效，不覆盖更早的有效记录；未在截止前完整上传的包也不作为最终有效提交。赛后只要求提供最终有效提交对应的模型包，不要求提供所有历史版本。

截止前更换方案，应提交完整的新结果和新声明；截止后不能补写或替换最终 SHA，也不能拿另一版模型匹配已经锁定的预测结果。

本次 B 榜共 **106 张图像：53 张原图和对应的 53 张翻转增强图像，全部参与评测**。演示程序只读取公开图像清单，为每张图输出空的 `instances`，不读取真实标注，不包含模型权重或隐藏答案。

## `result.json` 格式与评分

### 图像记录与类别

文件使用 UTF-8 编码。JSON 顶层必须且只能包含 `version` 和 `results`：

- `version` 固定为字符串 `"1.0"`。
- `results` 必须覆盖本次 B 榜全部 106 张图，每张图恰好一条记录，不得重复、遗漏或增加外部图像。
- 每条图像记录必须且只能包含 `image_id` 和 `instances`。
- `image_id` 是完整图像文件名，包含 `.jpg` 扩展名，并与公开清单完全一致。
- `instances` 是该图像的实例列表；没有预测时必须写 `[]`，不能删除整条图像记录。

下面只是单张图的格式片段，**不能当作完整提交**：

```json
{
  "version": "1.0",
  "results": [
    {"image_id": "IMG_332.jpg", "instances": []}
  ]
}
```

每个非空实例必须且只能包含三个字段：

| 字段 | 要求 |
| --- | --- |
| `category_id` | 整数 `0` 表示完整花穗，整数 `1` 表示不完整花穗 |
| `score` | `[0,1]` 范围内的有限数值，不能是布尔值、NaN 或 Infinity |
| `segmentation` | 必须且只能含 `size` 和 `counts` 的 COCO compressed RLE 对象 |

**训练标注和提交结果的类别编号不同：训练 COCO 标注的 `1/2` 必须分别转换为提交结果的 `0/1`。** 不接受第三类别，也不要提交 `__ignore__` 类别。不要额外添加 `bbox`、实例 ID 或其他字段。

### 掩码要求

- `size` 固定按 `[height,width]` 顺序填写；两项必须为整数，不能写成浮点数。本次 B 榜图像尺寸为 `[1152,2048]`，仍应逐图按公开清单核对。
- 必须先把预测掩码恢复至原图分辨率，再编码为真实 COCO compressed RLE。
- `counts` 必须是压缩 RLE 字符串，不接受未压缩的整数数组；编码必须完整、合法，与图像像素数一致，且实例前景不能为空。
- 不接受 Polygon、多边形坐标、二值图片路径或 Base64 掩码。
- 同一图中的不同花穗应分别输出实例，不能合成一个掩码。
- JSON 所有层级均不允许重复字段。任一必填字段缺失、类型错误、额外字段或非法实例都会使本次提交无效，不会只丢弃该条预测后继续评分。

使用 `pycocotools` 从二维二值掩码编码时，可参考以下片段；其中 `mask` 应是自己的原图尺寸预测掩码：

```python
import numpy as np
from pycocotools import mask as mask_utils

rle = mask_utils.encode(np.asfortranarray(mask.astype(np.uint8)))
rle["counts"] = rle["counts"].decode("ascii")
```

### 评分与忽略区域

最终分数为 COCO Mask mAP@[0.50:0.05:0.95]，对两个类别及十个 IoU 阈值取平均，范围为 `[0,1]`，**越高越好**。采用 101 点插值、`area=all`；每张图每个类别按置信度排序，最多取前 100 个实例参与评测，即 `maxDets=100`。

在每个 IoU 阈值下先匹配同类别普通真实实例。未匹配预测与该图全部忽略区域并集的交集面积，若达到预测面积的 50%，则该预测不计 TP、也不计 FP；否则计 FP。此规则对两类均生效。忽略区域不计入普通真实实例数量，也不是选手需要输出的第三类。

测试集不提供普通标注和忽略区域答案；公开校验器只检查格式，不能计算真实 B 榜分数。

## 文件大小限制

- `b_submission.zip` 不超过 **1 GiB（1,073,741,824 字节）**。
- `result.json` 解压后不超过 **1 GiB（1,073,741,824 字节）**。
- `solution_commit.txt` 不超过 **65,536 字节**。
- 赛后提交的真实 `solution.zip` 按题面要求：压缩包不超过 **5 GB**，解压后不超过 **10 GB**。它不放入比赛阶段的 `b_submission.zip`。

## 赛后复核要求

成绩确认后，进入排行榜 **Top10** 的队伍按通知提交最终有效声明对应的原始 `solution.zip`。赛事方依次核对 SHA-256 和字节数、检查代码与包内容、断网运行模型、比对预测并复算分数。**比赛阶段“格式通过”不代表真实 SHA 已核对，也不代表模型已经通过审核。**

真实模型包应按题面包含：

```text
solution.zip
├── model/                 # 模型权重
├── config/                # 配置
├── src/                   # 模型及推理源码
├── inference.py           # 统一推理入口
├── requirements.txt       # 依赖及版本
└── README.md              # 安装、推理和复现说明
```

材料使用相对路径，必要文件完整放入包内，不得依赖联网下载、分卷压缩或外部链接补齐。题面规定的复现环境为 Ubuntu 22.04、Python 3.10、PyTorch 2.2、CUDA 12.1、单张 NVIDIA GPU、Batch Size 为 1。使用特殊框架、自定义算子或其他版本时，应在模型包 README 中说明，并提供源码及自动安装或编译脚本。

真实模型须支持题面规定的入口：

```bash
python inference.py \
  --input_dir test_images/ \
  --weights model/best.pt \
  --output_path reproduced_result.json
```

集成模型、TTA、多阶段推理和自定义后处理也必须完整提交并说明。模型及推理流程必须与生成最终提交时一致；复核 Mask mAP 与榜单成绩的绝对差值原则上不得超过 **0.005**，该数值容差不允许用来更换模型、权重、配置或核心推理逻辑。

禁止测试集查表、硬编码答案、人工制作预测和读取隐藏标注。测试图像及预测结果不得用于训练、伪标签或人工标注；禁止外部数据及额外标注数据。允许使用可公开下载、可离线运行的预训练权重和开源模型，但应在模型包 README 中列明名称、版本和下载地址，禁止在线 API 调用。

原始包 SHA 或字节数不一致、包内容缺失、断网后无法运行、无法按规定复现或发现违规实现，均会导致审核不通过，并按赛事规则取消成绩或获奖资格。题面允许对首次因非核心环境说明不清导致的失败给予一次不超过 24 小时的补充说明机会，但**不能借此修改、重压或替换最终声明对应的原始 `solution.zip`**。

请在每次提交前生成真实声明，随结果一并提交，并妥善保存原包。赛后不能以“重新压缩了”“权重一样”“文件名没变”或“填错了”为由，使用不匹配的模型包替代最终提交对应的原包。
